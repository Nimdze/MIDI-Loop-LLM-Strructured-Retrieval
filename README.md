# MIDI Loop LLM Structured Retrieval

**Natural Language MIDI Loop Retrieval via Structured LLM Translation and Deterministic Scoring**

Companion code for the demo paper by **Nimrod Adar** (Engineering Department, Bar-Ilan University).
It bridges natural language and symbolic music by separating *semantic interpretation* from
*deterministic scoring*: a Large Language Model translates open-ended queries into bounded,
algorithmically-defined constraints, and a deterministic scorer ranks MIDI loops against them.

> 🔗 **Interactive demo:** <https://midi-loop-llm-retrieval.streamlit.app/>
> · demo source: [Demo-Natural-Language-MIDI-Loop-Retrieval…](https://github.com/Nimdze/Demo-Natural-Language-MIDI-Loop-Retrieval-via-Structured-LLM-Translation-and-Deterministic-Scoring)

## Overview

Modern music production relies heavily on short, single-instrument MIDI loops. Existing Music
Information Retrieval tools are optimized for audio or full pieces, and conventional retrieval
methods struggle with the precise logical constraints and per-musician customization that producers
need for symbolic loop retrieval: they capture broad similarity but cannot enforce strict
constraints (`not`, `only`), directional bounds, or tiered composition, and a context-free MIDI loop
is inherently malleable — its "feel" depends on the rendering synthesizer.

This project is built entirely on **structural extraction**. Instead of asking a model to judge
subjective qualities, it extracts measurable musical features, quantizes them into ordered semantic
levels, and uses the LLM only as a translator from natural language into that bounded schema. The
division of labor makes retrieval verifiable and debuggable, and lets users inject custom
definitions through an instructions prompt in real time — with no re-indexing.

## Pipeline

The system decouples linguistic reasoning from numerical ranking across three modular stages.

1. **Preprocess** — raw MIDI files are validated and, where needed, split into single-instrument
   loops and normalized for tempo and length. → `MIDI_PREPROCESSOR/`
2. **Analyze & quantize** — an analyzer extracts roughly **150 structural features across 11
   subcategories** (rhythmic density, spacing, grid, texture, harmonic intervals, and so on),
   adapting jSymbolic-style MIR to loop-level granularity. Drum tracks use a specialized four-limb
   decomposition (kick, snare, hi-hat/cymbals, toms). Raw continuous values are quantized into
   ordered semantic levels to prevent numerical hallucination during LLM inference, and stored in a
   SQLite database plus a JSON taxonomy. → `MIDI_ANALYZER_TAGGER/`
3. **Retrieve** — a dynamically compiled system prompt exposes the active taxonomy to an LLM, which
   acts purely as a translator: each returned target carries a **concept**, an intended **level**, an
   **importance** weight, and a directional **fallback** strategy (nearest, prefer more intense,
   prefer less intense). → `MIDI_LLM_SEARCH_ENGINE/`

A deterministic scorer then ranks files over an in-memory index using an ordinal step-distance
formula based on a weighted Gower similarity coefficient:

```
credit = importance × (1 − steps / max_steps)
```

Directionality-informed penalties punish deviations that move against the user's directional
intent, so the retrieval space relaxes strictly along the desirable paths.

## Repository layout

| Path | Description |
|---|---|
| `MIDI_PREPROCESSOR/` | MIDI cleaning, validation, splitting, slicing, and normalization. |
| `MIDI_ANALYZER_TAGGER/` | Plugin-based feature extraction, quantization, and taxonomy export. |
| `MIDI_LLM_SEARCH_ENGINE/` | LLM query-translation client and deterministic scorer. |
| `MIDI_LLM_SEARCH_ENGINE/experiments/` | Recorded runs of the six translator evaluation rounds — see its [README](MIDI_LLM_SEARCH_ENGINE/experiments/README.md). |
| `MIDI_EXPLORATION/` | Streamlit UI for importing, browsing, and validating analyzed libraries. |
| `default_dataset/` | Pre-packaged MIDI library ZIPs (ASF-4, HP-10, Cinematic, Dubstep) for quick-start. |
| `taxonomy.json` | Canonical merged taxonomy generated by the analyzer. |
| `system_prompt.txt` | Generated LLM system prompt (a snapshot of the compiled taxonomy prompt). |
| `feature_validation_ratings_*.json` | Expert panel ratings used in the qualitative taxonomy validation. |

> **Note:** the preprocessed per-dataset databases and `soundfonts/` are intentionally excluded from
> version control (they are large and regenerable). Run the preprocessor/analyzer to rebuild the
> databases, and supply your own SoundFont for playback.

## Getting started

Python 3.14 is required. Each package has its own `pyproject.toml`, so install them in development
mode into a single environment. For the exploration UI:

```bash
cd MIDI_EXPLORATION
python3 -m venv .venv
.venv/bin/pip install -e .
.venv/bin/pip install -e ../MIDI_PREPROCESSOR
.venv/bin/pip install -e ../MIDI_ANALYZER_TAGGER
.venv/bin/pip install -e ../MIDI_LLM_SEARCH_ENGINE
.venv/bin/streamlit run src/midi_exploration/app.py
```

FluidSynth is required for MIDI playback with SoundFonts (on Debian/Ubuntu:
`apt-get install fluidsynth fluid-soundfont-gm`; on macOS: `brew install fluid-synth`).

### Command-line entry points

```bash
# Preprocess raw MIDI into clean single-instrument loops
python -m midi_preprocessor process path/to/raw --output path/to/clean

# Analyze a file into tags + taxonomy
python -m midi_analyzer_tagger analyze path/to/file.mid --output ./output
```

## Evaluation (summary)

The companion paper reports a preliminary evaluation of the translation architecture:

- Pairwise correlation analysis over the extracted taxonomy confirmed discriminant validity, and a
  panel of three academically trained musicians rated 53 structural concepts at a mean **4.78 / 5**
  for accuracy and informativeness.
- Under a behavioral-testing framework, the translator achieved **97.2%** concept-presence accuracy
  and **100%** level-direction calibration across **434** lexically-distanced paraphrased queries.
- On compositional queries with explicit prioritization and directional constraints, it maintained
  **99.1%** importance-ranking accuracy and **100%** fallback accuracy.

These validate the core translation architecture; further evaluation is ongoing.
